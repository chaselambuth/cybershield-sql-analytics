# Model research and experiment design

Research cutoff: October 24, 2026, America/New_York. Primary research and official dataset pages were searched for intrusion detection, tabular classification, CPU inference, single-record latency, batch throughput, and recent tabular foundation models. This is a focused evidence review, not a systematic meta-analysis. Hardware, task, feature count, prevalence and latency definitions differ, so published timings are not pooled into a league table.

## Decision for this prototype

Benchmark **logistic regression, linear SVM, random forest, extra trees, histogram gradient boosting, XGBoost, LightGBM and CatBoost** on the same seven SQL features. Boosted trees are strong candidates for the quality/compute tradeoff; none is established as the universal fastest or most accurate model. Keep linear models as low-complexity latency references and retain the existing SQL rules as detection-quality references. A small, interpretable feature set may favor simpler methods.

Use the local measured Pareto frontier (missed positive windows, false alerts and warm single-window P95) rather than accuracy alone or an arbitrary weighted score. A point on this frontier is only non-dominated among these configurations on this machine and development slice. Six correlated positive development windows cannot establish a generalizable model ranking.

## Local protocol

The notebook pins the existing SQL feature run and hashes its CSV/configuration. No model sees IP addresses, timestamps, labels, prior predictions or historical fields as inputs. Labels identify evaluation targets only. Imputation and scaling fit on training data alone. Class weights use training labels; the development set retains its natural prevalence.

Parameters are fixed before running this comparison; there is no grid search or early stopping on the development set. Training, calibration and development use the prototype's existing chronological intervals. They can share one campaign, so chronological separation does not establish episode independence. Thresholds use only benign calibration scores and a 1% empirical false-positive budget, with ties excluded conservatively. This budget does not guarantee 1% future false positives. Calibration attack windows are not used to select thresholds.

Each candidate is fitted three times in seeded, randomized interleaved order. Report median and maximum fit time; three fits are insufficient for a reliable training-tail estimate. Warm prediction timing uses five warm-up calls, 60 measured single-row calls, and 25 measured calls at batch sizes 32, 256 and the full development set. Model order is randomized within each repeat. Every method receives the same sampled rows. Report median and empirical P95 call latency; these are repeated-call summaries, not confidence intervals or service-level guarantees.

Pipeline timings include imputation and the candidate's required transformations. Estimator-only timings transform all inputs outside the timed region. Both include Python dispatch and score extraction. One thread is requested for BLAS/OpenMP and estimator-specific CPU controls. Latency includes output creation but excludes SQL retrieval, HTTP, deserialization, feature construction and five-minute window waiting. A separate read-only SQL retrieval measurement includes query execution, local transfer and DataFrame materialization, but does not rebuild the feature tables. No concurrent load isolation or cold-start benchmark is claimed. CPU frequency, background load and thermal state can affect results.

Model bytes are uncompressed joblib serialization size, not peak RAM. Scores such as SVM margins are not calibrated probabilities. Compare average precision, caught/total positive windows, false/total benign alerts, precision/recall/F1 and observed latency. Keep all raw repetitions and the environment manifest. Reruns will produce different timings.

## Source-selection evidence

- [Original CIC-IDS2017 source and topology](https://www.unb.ca/cic/datasets/ids-2017.html): the local original labeled-flow archive supplies endpoints and time fields needed by the SQL task. The audit quantifies actual defects rather than relying on the dataset name.
- [CNS2022 corrected-release documentation](https://intrusion-detection.distrinet-research.be/CNS2022/CICIDS2017.html), [download guidance](https://intrusion-detection.distrinet-research.be/CNS2022/Dataset_Download.html), [archive index](https://intrusion-detection.distrinet-research.be/CNS2022/Datasets/): corrected extraction and finer label distinctions require an explicit target policy. Attempted traffic must not silently become a known benign or successful attack target. The notebook audits the complete Tuesday member only.
- [Official UNSW-NB15 documentation](https://research.unsw.edu.au/projects/unsw-nb15-dataset): describes 2,540,044 records in four CSVs, nine attack families and predefined ML subsets. The official SharePoint download returned HTTP 403 during this review. Endpoint/time schema, quality and current usable row counts therefore remain unverified. Academic use requires the requested citations; commercial use requires agreement. A pre-split ML table is not assumed to preserve fields needed for source/time aggregation.

Select on required endpoint/time fields, interpretable clocks, label provenance, usable temporal coverage, target support, acquisition/provenance, and implementation effort. Do not select whichever dataset gives the highest model accuracy. The corrected and original CIC releases derive from the same capture, so comparing them is a source-quality decision, not external validation. UNSW is the independent-capture candidate, pending actual access and audit.
